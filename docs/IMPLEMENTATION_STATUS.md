# 当前实现与待完成项

更新于 2026 年 11 月 17 日。本仓库为依据 WorkFactory 论文描述编写的独立复现实现。以下区分代码实现、实际执行和未完成工作。

## 本次已修改

- prompts/03_plan.txt 要求每份参考文件在现有 role 字段说明用途、受众、使用方式和格式理由，交付要求在 description 中说明格式理由。格式选择依据真实工作需求，不设置文件种类或数量配额。
- 正式报告、制度、合同、课程讲义、演示、计算表和系统导出按实际用途选用合适载体，禁止因生成便利而默认降为 Markdown。MD 和 TXT 在业务明确适用时仍可使用。
- 真实文件的版式、表格、图形或证据作用需要保留时，保留原始格式；正文摘编须说明范围、改编理由和损失的信息。
- 职业定义、技能说明和构造审计资料默认属于构造资料，仅在求解确需时进入参考文件，避免无业务用途的文件堆积。
- prompts/04_build.txt 要求实际生成对应格式并读回，禁止改后缀冒充文档或未经允许转成 MD。
- prompts/05_construction_review.txt 与 contracts.py 新增必查 format_fitness。审核遗漏该项或该项失败却宣称通过时，程序拒绝结果。
- prompts/09_teacher.txt 明确按用户请求交付，不能因写入便利自行改成 MD、TXT 或 CSV。

这些修改通过 56 项本地测试。已有三条 GPT 联网任务使用修改前的格式规划提示词生成，不能作为本次格式改进有效性的证据。新提示词尚未进行新批次端到端验证。旧批次和旧评审记录保留；新实验须使用新输出目录。

## 已有实现及运行证据

- BLS 2018 SOC、O*NET 31.0 来源池已接入，包含 23 个 SOC 大类、867 个细分职业和 1016 条 O*NET 职业记录。
- skills CLI 采集配置的 8 个仓库，当前本地快照共 640 份文档，639 份达到正文长度门槛。该数字只覆盖配置仓库，不代表 skills.sh 全站。
- 单轮意图生成、意图审核和信息支撑图规划已实现。构建、内容审核、独立探针、修复、工作保留审核和独立教师目前使用工具循环。
- GPT Responses 原生 web_search、真实交付物下载、分段续传、解析、来源 URL 和内容哈希保存已实现，并用于三条混合来源任务。
- 构造来源仅在构建阶段只读挂载到 /sources，探针和教师不挂载该目录，只能看到物化后的任务材料。
- 三条 GPT 任务的环境检查、独立探针和教师执行已完成，导出候选轨迹。费用按保存的用量和用户提供的单价估算，来源准备、失败尝试和联调开销均纳入。
- Dockerfile、源码、配置、提示词和测试进入 GitHub。密钥、本地下载数据、运行结果和 Docker 镜像不进入仓库。
